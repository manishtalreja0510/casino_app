# API Principles

Normative principles for every API surface (player REST, admin REST, WebSocket). Concrete rules: `api-conventions.md` (REST) and `websocket-conventions.md` (Socket.IO). Non-negotiables they derive from: `../00-project/system-rules.md` (rules 1, 2, 6, 23).

1. **REST for everything non-realtime; WS for gameplay only.** Auth, profile, wallet, lobby data, KYC, payments ride `/api/v1`. Socket.IO (`/lobby`, `/game`) carries only live match/table/lobby traffic (ADR-007). Anything that survives a page of latency is REST.
2. **Server authoritative — client input is intent, never truth.** No request or event carries a balance, outcome, timer expiry, or hidden-info claim the server accepts. Every input is validated, re-derived, or rejected (rules 1–2).
3. **Contract-first.** `packages/contracts` holds the OpenAPI spec, JSON Schemas, WS event schemas, and the error-code registry. The Dart client (`apps/mobile/packages/api_client`) and server validation are **generated** from it. Hand-written DTOs are forbidden — a type that isn't in contracts doesn't exist.
4. **Additive evolution within `/v1`.** Add optional fields, new endpoints, new enum values (clients must tolerate unknown values). Never remove/rename/retype within a version (rule 23). Breaking change = new version + migration plan.
5. **Sideload-tolerant versioning.** Off-store clients update on their own schedule; weeks-old clients are normal, not an edge case. Design for old clients first; server min-version enforcement via forced update (426, ADR-017) is the **backstop**, not a substitute for additive discipline.
6. **Every mutation idempotent or naturally safe.** State-changing endpoints take `Idempotency-Key`; retries are always safe (rule 6). The mobile retry queue depends on this — non-idempotent mutations don't exist by convention.
7. **Deny-by-default authz.** Every endpoint declares its guards (auth, device binding, signing, role, KYC level, feature flag); an endpoint with no declaration is unreachable. Admin surface additionally: 2FA + RBAC + optional IP allowlist.
8. **Validation at the edge, from contract schemas.** Requests are validated against the generated schemas before any handler runs; the domain layer re-validates semantics. Unknown request fields are rejected on input (strict) while clients tolerate unknown response fields (loose out, strict in).
9. **No PII in URLs.** Paths and query strings are logged everywhere (WAF, LB, proxies): opaque UUIDv7 ids only; emails, names, documents, tokens go in bodies/headers over TLS only (rule 15).
10. **Consistent envelopes everywhere.** One success shape, one error envelope (`{error: {code, message, details?, traceId}}`) — including 4xx/5xx generated by middleware, guards, rate limiter, maintenance mode, and anything else behind the WAF. A client must never need to parse HTML or guess at a bare-string body from our origin. (Responses generated *by* the WAF/CDN itself are the one documented exception; the client treats non-JSON as `network`/`unknown` per `../01-architecture/frontend-architecture.md` §7.)
